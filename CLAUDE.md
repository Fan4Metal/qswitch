# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

qswitch is a Windows-only keyboard layout switcher in the spirit of Punto Switcher and Caramba Switcher, written in Rust with egui/eframe 0.36 (glow). Two taps of Shift convert the word just typed into the other layout of a pair (`ghbdtn` → `привет`) and switch the window to that layout; repeated, the gesture puts the word back (a toggle of the last word, no timer). It lives in the tray, shows the current layout there, and follows rules per program (do nothing in games and remote desktops, start IDEs in Latin). Priorities: a key never waits for the UI (the hooks run on their own thread), nothing typed is written to disk, no telemetry, start-up speed, a minimal interface. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives). `local/` (git-excluded) holds the plan (`PLAN.md`) and `TODO.md`.

The name is `qswitch` everywhere: the display name (UI, window title, READMEs, installer, `%APPDATA%\qswitch`, `%LOCALAPPDATA%\Programs\qswitch`, `qswitch_<ver>_Setup.exe`) and the identifier (Cargo package, `qswitch.exe`, the GitHub repo `Fan4Metal/qswitch`), as qview and qrec.

## Commands

```
uv run build.py                  # closes a qswitch.exe running from target\, then cargo build --release
cargo build --release            # target\release\qswitch.exe (fat LTO)
cargo test                       # unit tests: the engine (gestures, the toggle, resets), settings, layouts (needs installed layouts), the tray icon, icon
cargo clippy --all-targets       # must stay warning-free
python tools/make_release.py     # tests, release build, dist\qswitch_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\qswitch.exe --export-icon file.ico   # the app icon for the installer / the README
.\target\release\qswitch.exe --hidden     # start in the tray (the autostart entry); --quit, --pause, --resume talk to the running copy
set RUST_LOG=debug               # env_logger; the debug build has a console
set QSWITCH_TRACE=1              # the key trace (the Status page's check box) on from the start, to trace.log next to the settings
cargo run --example typing       # does an egui field take what the hook injects (Backspaces, Unicode text, a layout request)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user, with an "autostart" task writing the same `Run` value the program writes, and `[UninstallRun] --quit`. `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. `windows-sys` for the Win32 API, the `windows` crate only for the COM interfaces of UI Automation (`selection.rs`). These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step.

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\qswitch.exe`; when the change concerns the installed copy (installer, autostart, portable mode) or the user runs the program all day (they do: it is a tray program), `python tools/make_release.py --no-tests --install` replaces the installed copy silently (it closes the running one first; the settings are saved as they change, so nothing is lost).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `qswitch.exe` locks the release binary; `build.py` closes it first (`post_close`: WM_CLOSE to its windows, which the subclass answers by ending the program; killed after 3 s). Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--version`, `--help`, `--hidden`, `--quit`, `--pause`, `--resume`; the release exe has no console, so the printing modes call `win::attach_parent_console`), one instance (`instance::claim` before anything else: a second start hands its command to the first and exits), the settings read before the window is built (its saved place goes into the `ViewportBuilder`; `with_visible(false)` for `--hidden`), the panic hook, `NativeOptions` (glow, `centered` only without a saved place), `eframe::run_native`.
- **`engine.rs`**: the state machine, pure (no Win32), fully under tests with made-up layouts. Fed every key as the hook sees it (`Key`: vk, down, time, the character the key gives in each layout of the pair, which layout the window is in), it keeps the line typed since the last reset as `Typed` keys (each knowing its character in both layouts and which is shown), follows the double tap (`Trigger::DoubleShift`/`DoubleCtrl`: a tap is ≤ `tap_ms`, the second starts ≤ `gap_ms` after the first ends, any other key in between cancels; `Trigger::Pause` swallows Pause), and answers with a `Verdict`: swallow or not, plus `Effect`s (`SwitchLayout`, `ToggleLayout`, `ConvertSelection` for the gesture with nothing typed, `Replace { backspaces, text }`, `Converted` for the UI). The gesture flips the last word (the non-space keys before the trailing spaces) to the other layout of where its last key is shown, so a repeat puts it back, however late; the line's earlier words are never touched. Backspace pops a key, Ctrl+Backspace a word, navigation keys and shortcuts with Ctrl/Alt/Win reset the line, a key with no character in the current layout resets it, a layout outside the pair resets it. Caps Lock as the switch is swallowed and toggles (Shift+Caps Lock passes). `set_enabled(false)` makes it let everything through (a rule's Off, paused).
- **`indicator.rs`**: the badge with the layout's letters near the caret, a layered topmost tool window (no activation, clicks go through, `SetLayeredWindowAttributes` alpha, a rounded region) owned by the hook thread and painted by GDI (Segoe UI bold, `indicator_size` pt (6–32, default 10; the paddings and corners scale with it) at the DPI of the window in front, `GetDpiForWindow`; with `indicator_colored` the layout's colour of `indicator_colors` as the background, a darker border and white letters, else the taskbar's grey; the badge's settings travel as one `indicator::Config` (`Settings::indicator_config`) inside `hook::Setup`; a changed look (size, colours, duration) is flashed beside the pointer by `configure`, and the window's "Show" button does the same through `hook::preview_badge` (`WM_PREVIEW`), so the controls show what they set; dark or light after `SystemUsesLightTheme`). Modes (`settings.indicator`): `off`, `on_switch` (shown for `indicator_ms` when `poll_layout` sees another layout; not for the first seen), `always` (moved on every caret event); with `indicator_on_caret` (in `on_switch`) also for a moment when the caret is placed: `caret_placed` on a left button down (the mouse hook; the caret before it noted, shown only if it moved), a focus change and a foreground change, looked for 60 ms later (`PLACED_TIMER` on the badge's window, `placed_due`), at a caret only (a strict question to the caret thread; no caret, no badge). The caret: `EVENT_OBJECT_LOCATIONCHANGE` with `OBJID_CARET` → `caret_of_thread` (`GetGUIThreadInfo` of the event's thread, no call into the other process) → screen rectangle, forgotten on a foreground change; without one, the hook thread asks the caret thread (`caret.rs`) and waits up to 400 ms for the answer (`asked`, `WM_CARET`), else the badge goes beside the mouse pointer; a caret event without a Win32 caret (Chromium's, once its accessibility is on) asks again while the badge follows the caret. Kept inside the monitor's work area, above the caret when there is no room below.
- **`selection.rs`**: the selected text of the focused element through UI Automation (`windows` crate: `CUIAutomation8` → `IUIAutomation2` with 500 ms connection and transaction timeouts, `GetFocusedElement`, `TextPattern.GetSelection`), on a thread of its own started by the hook thread for `Effect::ConvertSelection` (the gesture with nothing typed): the text is converted with `layout::convert_text` (character by character, each to the other layout of the pair, by the key that types it), typed over the selection with `inject` (no backspaces; `\n` as Enter, `\t` as Tab) and the window switched to the layout of the result; no selection, or a terminal in front (`TERMINALS`, where typing does not replace a selection), gives the layout switch alone. No clipboard and no Ctrl+C (a terminal's interrupt).
- **`caret.rs`**: the caret of a program that keeps no Win32 caret (Chromium/Electron: VS Code, browsers; WPF, UWP), on a thread of its own (`spawn`; UIA made at the first question, 300 ms timeouts; only the latest of queued questions answered): MSAA `OBJID_CARET` of the focus window (`accLocation`), else UIA `TextPattern2.GetCaretRange`, else the end of `TextPattern.GetSelection`; an empty range's own rectangle, else the right edge of the character before, else the left edge of the one after. A strict question (a caret just placed) counts only an element that takes text (a value not read-only, else an edit control); an MSAA caret marked invisible is none. `cargo run --example caret` prints the focused element and what it finds in the window in front and how long it took.
- **`layout.rs`**: `installed()` (`GetKeyboardLayoutList`, names via `LCIDToLocaleName`/`GetLocaleInfoEx`), the foreground window's layout (`GetGUIThreadInfo(0).hwndFocus`, else the foreground window; `GetKeyboardLayout` of its thread), `switch_to` (`WM_INPUTLANGCHANGEREQUEST` posted to the focus window and the foreground window), `Table::of(hkl)`: what each vk types with Shift and Caps Lock, by `ToUnicodeEx`, plus the reverse map `key_of(char)` (the plain key first) that `convert_text` uses; with bit 2 of the flags (Windows 10 1607+: does not touch the dead-key state); control characters and dead keys are `None`. A layout's id in the settings is the HKL in hex.
- **`hook.rs`**: the hook thread (`THREAD_PRIORITY_HIGHEST`, its own `GetMessageW` loop): `WH_KEYBOARD_LL` runs the engine in the callback (microseconds) and queues `Job`s (`Switch`, `Replace`) that are done on `WM_JOB` after the callback returned, so the key that caused them has reached its window first; `WH_MOUSE_LL` resets the line on a button; `SetWinEventHook` for `EVENT_SYSTEM_FOREGROUND` (the program's rule, a forced layout, the line reset, `Event::Foreground`) and `EVENT_OBJECT_FOCUS` (reset); `WM_TOGGLE` from the tray (the last foreground window that is not the taskbar, `is_taskbar`, when it is a program's window, `is_app_window`: shown, not minimized, not cloaked, not a tool window, not the desktop, checked again at the click, else the topmost such window in the z-order, `top_app_window`, gets the other layout through `layout::switch_window` in the background, and the taskbar in front too, for the shared input method; the focus is never moved; while the taskbar is in front, the layout polled for the tray and the badge is that window's, `shown_layout`, since the taskbar's own does not change); a 150 ms timer polls the layout (`Event::Layout` when it changes: Alt+Shift is not seen otherwise). `release_raw_input` (called from `App::new`) unregisters the raw keyboard and mouse input winit registers for its device events: while a process holds it, Windows does not call that process's `WH_KEYBOARD_LL` for keys typed into its own windows, so the gesture did nothing in the window's own "try here" field (found with the debug logging of the callback: the hook thread ran, the callback was never entered while the window was in front). Injection: `SendInput` with `VK_BACK` presses and `KEYEVENTF_UNICODE` text (the same whatever layout the window is in), `dwExtraInfo = MAGIC` so the hook lets it by; other injected input (other tools' `SendInput`) is treated as typed. The UI gives it a `Setup` (`reload`), `set_paused`, `stop`; it answers with `Event`s on an mpsc channel plus `ctx.request_repaint()`. Shift is followed in the thread for the tables; Caps Lock by `GetKeyState`. On every key down the engine's held keys are checked against `GetAsyncKeyState` (`Engine::forget_released`): a release the hook missed (Win+L, Ctrl+Alt+Del, an elevated window) would otherwise leave a key held for good, and no Shift would be a tap alone. The state lives in a thread-local `RefCell` (`with_state` refuses re-entry).
- **`settings.rs`**: JSON through serde (`%APPDATA%\qswitch\config\settings.json`, `#[serde(default)]`, `.tmp` + rename, numbered background saves), or `qswitch.json` next to the exe when that file exists and can be written (portable mode, `settings::location`, decided once per run; the portable zip ships it empty). Saved whenever they change (`App::follow_settings`), not at exit: the program may be ended from the tray or by the installer. Holds the window's place (eframe's `persistence` feature is off), the gesture (`trigger`, `caps_lock_switch`, `tap_ms`, `gap_ms`), the pair of layouts (`layouts`: two HKL ids, else the first two installed), `close_to_tray`, the rules (`rules`: exe file name, case-insensitive, `mode` off/first/second; mstsc, VirtualBox, VMware, vmconnect off by default). `checked()` puts hand-edited values back in range.
- **`app.rs`**: the eframe `App`. `logic` (called before every frame, and while the window is hidden whenever something calls `request_repaint`) takes the hook thread's events, the window's queued messages (`window::take_hooked`), saves changed settings and gives the hook thread a new `Setup` when its part changed, and keeps the tray icon in step. `ui`: toolbar (Pause/Resume, a red warning while the key trace is on and another while conversions are kept (a click opens the Status page), theme, About, update), a left list of pages, the page (`ui/pages.rs`). The window's close button hides it to the tray (`close_to_tray`), `Exit` in the tray menu, `--quit`, a `WM_CLOSE` from outside and `taskkill` end it (`quit`: settings written, hooks stopped, icon removed, `process::exit`). The window's place is noted each frame and applied to the settings once it has rested a second.
- **`window.rs`**: the main window's subclass (`SetWindowSubclass`): the tray icon's messages (a click or Enter on it, `NIN_SELECT`/`NIN_KEYSELECT`, calls `hook::toggle_layout` and nothing else: no window is shown or brought forward, the window opens from the menu only; the menu's choice is queued), `WM_SYSCOMMAND SC_CLOSE` (the close button, Alt+F4: queued as `CloseButton`, the app hides or ends), a bare `WM_CLOSE` (queued as `CloseNow`: end), `WM_QUERYENDSESSION`/`WM_ENDSESSION` (save), `TaskbarCreated` (Explorer restarted: the icon is added again), `WM_WINDOWPOSCHANGING` (a `--hidden` start: eframe shows the window after its first frame whatever `with_visible(false)` said, and dropping `SWP_SHOWWINDOW` does not stop it, so the window is cloaked in `App::new` and `keep_hidden` makes the subclass post `WM_HIDE_AGAIN` on that show, which hides and uncloaks it, and add `SWP_NOACTIVATE | SWP_NOZORDER` to every `SetWindowPos` until then: `ShowWindow` activates with a second one), `Remote` commands from `instance.rs`. `bring_back`/`hide`: `ShowWindow`; eframe reads the real visibility, so no viewport command is needed. `is_elevated` lets the tray messages and `WM_COPYDATA` through UIPI when elevated.
- **`tray.rs`**: `Shell_NotifyIconW` with an icon of the layout's two letters drawn by GDI (bold Segoe UI at 11/16 of the small icon size, white text on black turned into alpha, premultiplied, `CreateIconIndirect`), dark on a light taskbar (`SystemUsesLightTheme`), grey while paused; the menu (Show, Pause/Resume with a check mark, Exit). From metalamp's `tray.rs`.
- **`instance.rs`**: the named mutex `Local\qswitch.<hash of the exe path>` and a message-only window of a class with the same name; a later start sends its command (`show`, `quit`, `pause`, `resume`) in a `WM_COPYDATA`; `--quit` waits up to 5 s for the first to go (the installer). The receiver queues `Hooked::Remote`.
- **`autostart.rs`**: the `Run` value `qswitch` = `"<exe>" --hidden` under HKCU; `is_enabled` compares with this exe, so a moved copy reads as off.
- **`icon.rs`** draws the app icon procedurally (a key cap split by a diagonal, blue with a white A above, white with a graphite Я below; layers ≤ 24 px without the letters); `build.rs` includes it via `#[path]` to write the `.ico` embedded by `winresource` and `app_icon_{64,128,256}.rgba` into `OUT_DIR`; `main::embedded_icon` and `ui::app_icon` use those, so nothing is rasterised at start-up.
- **`update.rs`**: the opt-in update check (off by default, once a day at start-up, "Check now" in About): `win::https_get` (WinHTTP) asks `api.github.com/repos/…/releases/latest`, `tag_name` is picked out of the JSON by hand, a newer release shows `ui::update_button` beside About, opening the release page built from `CARGO_PKG_REPOSITORY`. `cargo test update -- --ignored` asks GitHub for real.
- **`caption.rs`**: `DWMWA_USE_IMMERSIVE_DARK_MODE` for the caption, `WM_NCACTIVATE` off and on to repaint it (Windows 10 repaints it only on the next non-client repaint), `cloak` against the white flash at start (not for a `--hidden` start).
- **`win.rs`**: `error_box` (user32 `MessageBoxW` declared by hand), `attach_parent_console`, `shell_open` (`ShellExecuteW`; eframe's `links` feature is off), `https_get`, `wide`.
- **`ui/`**: `app_icon`, toolbar buttons with a painted icon (`icon_button`), `theme_button`, `about_button`, `update_button`, `close_cross`; `ui/about.rs` the About modal; `ui/pages.rs` the pages: Status (hooks, paused, the layout and the program in front, the pair, a "try here" field (`App::try_text`: the gesture works in it as in any window), the last 20 conversions kept in memory while `keep_conversions` is on (off by default; the check box beside the heading; turning it off clears the list), a check box that writes a trace of every key, job and window change to `trace.log` next to the settings: `hook::set_trace`, `Event::Trace`, off at every start), Settings (the trigger, the pair, Caps Lock, the badge near the caret with its size, colours and a "Show" button, autostart, close to tray, the timings), Programs (the rules, an "add" field and a combo box of the programs with a window now, `hook::running_programs`, listed every other second while the page is shown, the one that was in front before the window first). Esc hides the window like the close button when nothing in it has the focus and no list is open.
- **`ui/icons.rs`**: the painted icons shared by the family (the default fonts lack many symbols), on a 14-point grid with 1.3-point lines. A new icon is added there on the same grid and checked next to the others with `cargo run --example icons`, not drawn ad hoc in a panel.

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`); the language follows the Windows UI language (`i18n::system_lang`, `GetUserDefaultUILanguage`) unless chosen in About (`i18n::LangChoice`, `system`/`en`/`ru` in the settings; applied in `main` before any text is made and at once when changed). Strings are built every frame, so nothing caches translated text. Log messages, CLI output and technical errors stay English.
- Persisted state (`settings.json`): `theme`, `language`, `check_updates`, `last_update_check`, `window`, `close_to_tray`, `keep_conversions`, `trigger` (`double_shift`/`double_ctrl`/`pause`/`off`), `caps_lock_switch`, `indicator` (`off`/`on_switch`/`always`), `indicator_ms`, `indicator_size`, `indicator_colored`, `indicator_colors` (two `#RRGGBB`), `indicator_on_caret`, `tap_ms`, `gap_ms`, `layouts`, `rules`. Autostart lives in the registry only.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`, the last number raised by one (after `0.1.0`, `0.1.1-dev`), and `build.rs` appends `git describe --tags --always` (`0.1.1-dev (v0.1.0-2-g4bd494d)`); a release version is shown as is. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version (`X.Y.(Z+1)-dev`).
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`) and ends the program. `f32::clamp` panics when its bounds cross.
- The hook callback must stay short (no I/O, no locks held long, no `SendMessage` to other processes): a callback later than 300 ms makes Windows drop the hook silently. Anything slow is a `Job` or an `Event`.
- Nothing typed is ever written to disk or sent anywhere (except the trace the user turns on for a check): the line lives in the hook thread's memory and is dropped on every reset; the Status page's list of conversions is in memory only.
- Commits in this repository end with a `Co-Authored-By: Claude <model> <noreply@anthropic.com>` trailer naming the Claude model doing the work (e.g. `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`); this overrides the global "no Co-Authored-By" rule for this repo only.
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine (the caption can, from a DPI-aware process); keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)`. A launched window takes the focus: warn the user before launching test windows and before any simulated global mouse or keyboard input, and close test windows with `taskkill /PID` (WM_CLOSE, which this program answers by ending). The end-to-end check of the gesture: a script starts Notepad, brings it to the front (a tap of Alt, then `SetForegroundWindow`), types with `keybd_event`, taps Shift twice and reads the Edit control with `WM_GETTEXT` (`ghbdtn` → `привет`, the layout `04090409` → `04190419`); it types into whatever is in front, so it runs only after a warning.
